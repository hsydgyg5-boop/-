تقرير فحص وإصلاح مشروع مزاجي للاستضافة — الإصدار v5
التاريخ: 2026-10-29

أهم الإصلاحات
1. إصلاح تجهيز بيئة Python عندما تكون .venv موجودة لكن pip مفقود: تجربة ensurepip، ثم استخدام pip النظام لتجهيز البيئة، ثم مسار توافق يثبت أدوات pip داخل site-packages الخاص بالبيئة، ثم تجربة virtualenv المتاح. لا يبدأ المشروع إذا كانت لديه مكتبات لازمة وفشل تثبيتها؛ ويُكتب سبب الخطأ في سجل التشغيل.
2. تحسين تشخيص تثبيت المكتبات وإعادة المحاولة عند الفشل، وفحص pip check بعد تثبيت الاعتماديات. يعتمد نجاح التنزيل على توفر مستودع الحزم واتصال الشبكة وتوافق إصدارات الحزم مع Python.
3. رفع حد ملفات المستخدم الذي تتحكم به الإدارة إلى 2,147,483,647 بدل السقف السابق. هذا حد عددي لإعداد الحساب، وليس مساحة تخزين غير محدودة؛ تظل قيود القرص والمنصة وعدد الطلبات مطبّقة.
4. تعديل بطاقة مدير الملفات بحيث يظهر الاسم الحقيقي الذي رفعه المستخدم أولاً كما هو، بالعربية إن كان الاسم عربيًا وبالإنجليزية إن كان إنجليزيًا، وتظهر التسمية العربية الوصفية في سطر ثانوي. لا تغيّر التسمية أسماء الملفات أو المسارات.
5. تحسين تصنيف ملفات بيانات البوت مثل db.json وusers.json وbalances.json وpoints.json وservices.json والملفات ذات امتدادات .db/.sqlite، وتصنيف المجلدات مثل factory_storage بوصف عربي واضح مع إبقاء الاسم الحقيقي.
6. إضافة تنزيل نسخة احتياطية كاملة من لوحة الإدارة تشمل db.json ومجلدات USERS ومشاريع المستخدمين وphp_files ومجلد backups، مع manifest يعرّف صيغة النسخة وتعليمات عربية. تستثنى بيئات قابلة لإعادة الإنشاء مثل .venv وvenv وnode_modules ومجلدات cache، كما يستثنى مفتاح الجلسة .session_secret.
7. إضافة استعادة نسخة ZIP كاملة من لوحة الإدارة. تتحقق الاستعادة من صيغة النسخة، والمسارات، والتكرار، والروابط الرمزية، وتفحص حجم الملفات المعلن قبل فحص بيانات ZIP، وتستخرج إلى منطقة مرحلية، وتعيد كتابة مسارات المشاريع للسيرفر الجديد، وتوقف المشاريع بعد الاستعادة لتحتاج تشغيلها يدويًا.
8. قبل الاستبدال، تنشئ الاستعادة نسخة رجوع تلقائية من قاعدة البيانات والملفات الحالية؛ وإذا فشل التبديل أو حفظ قاعدة البيانات، تحاول إعادة الملفات وقاعدة البيانات السابقة. لا تضع نسخ pre_restore السابقة داخل نسخة الرجوع الجديدة لمنع تضخم النسخ بصورة متكررة.

نتائج الاختبارات المحلية المنفذة في هذه الجولة
- PASS: إنشاء venv فعلية بدون pip ثم نجاح إصلاح pip عبر مسار ensurepip.
- PASS: تصنيف مجلد factory_storage المحتوي على ملف قاعدة بيانات دون تغيير اسم المجلد الحقيقي.
- PASS: استعادة نسخة اختبار تتضمن مستخدمًا ومشروعًا وإعادة ضبط حالة السيرفر إلى متوقف والمسار إلى المضيف الحالي.
- PASS: تنزيل النسخة الكاملة من دالة التصدير الفعلية، ثم استعادة ناتج ZIP نفسه بنجاح.
- PASS: رفض أرشيف يحاول الكتابة عبر ../ دون تغيير قاعدة البيانات الحالية.
- PASS: عند فرض فشل الحفظ النهائي، رجعت الملفات وقاعدة البيانات السابقة.
- PASS: السماح بحد ملفات قدره 1,000,000,000، وتقييد القيمة الأكبر من الحد الرقمي المحدد.
- PASS: py_compile لملفات Python.
- PASS: فحص JavaScript بوساطة node --check لملفات JS والكتل البرمجية المضمنة في صفحات HTML.
- PASS: فحص سلامة أرشيف ZIP النهائي بعد إنشائه.

حدود يجب توضيحها
- بيئة الفحص المحلية لا يتوفر فيها Flask الحقيقي، كما تعذر الاتصال بمستودع الحزم لتنزيله؛ لذلك لم يُشغّل خادم Flask حقيقي ولم ينفذ اختبار HTTP كامل أو نشر إلى Railway/الاستضافة الفعلية. اختُبرت دوال المسارات والنسخ والاستعادة محليًا باستخدام طبقة اختبار معزولة، إضافةً إلى اختبار venv حقيقي لفقدان pip.
- حد رفع الطلب الحالي في التطبيق هو 500 MiB للملف المرفوع. إذا تجاوز ZIP هذا الحجم فسيرفضه التطبيق، وقد تفرض الاستضافة/الوكيل حدًا أقل.
- لا يمكن ضمان تثبيت مكتبة يتطلب تنزيلها إذا كانت الشبكة أو مستودعات الحزم محجوبة، أو إذا كانت الحزمة لا تدعم إصدار Python المثبت على المضيف. في هذه الحالة سيعرض سجل التشغيل سبب الفشل بدل تشغيل المشروع وهو ناقص الاعتماديات.
- حد الملفات لا يتجاوز قيود سعة التخزين الفعلية. ولدوام الملفات عبر نشرات Railway، يجب ربط Volume فعليًا على /data؛ لا يستطيع ملف ZIP تغيير إعدادات الخدمة داخل حساب الاستضافة.
- النسخة الاحتياطية كاملة وحساسة وقد تتضمن بيانات حسابات ومفاتيح API وملفات المشاريع. احتفظ بها بمكان خاص ولا تشاركها علنًا.
